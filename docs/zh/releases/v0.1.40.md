# MyDB v0.1.40

发布日期：2026-11-23

本版聚焦 OLAP 大范围扫描的吞吐，不改 SQL 语义、不引入列存假设：在页级 zone map
裁剪之后，把剩余页的**行解码**按页分块并行执行，并在返回前恢复页序。

## 核心变更

- **并行页扫描**：`scan_pages_filtered` 在 `LIMIT` 为空且候选页 ≥8 时，按连续页块分发给
  最多 8 个 worker；每个 worker 独立读取/解码页面，主线程按页号合并，行顺序与串行路径一致。
- **精确语义不变**：zone map 仍在 `unpack_page_rows` 前裁剪；worker 使用相同的
  `RowPredicate` 逐行过滤，不存在近似或采样。
- **`LIMIT` 保持串行**：遇到前 N 行立即停止，不投机解码后续页。
- **全局并发配额**：同时进行的并行扫描数按 `CPU 核数 / 单查询 worker` 推导并封顶 4，
  避免多连接把线程数乘爆；配额耗尽时自动退回串行。
- **可运维开关**：`MYDB_OLAP_SCAN_THREADS` 覆盖自动并行度；设为 `1` 即完全禁用并行路径。
  默认取 `available_parallelism`，上限 8。
- **小扫描零开销**：候选页少于 8、`LIMIT` 存在、或只有单核时，不创建线程、不进入并行分支。

## 正确性验证

- 新增 `parallel_page_scan_preserves_page_order_and_filtering`：3000 行、跨越并行阈值，
  `BETWEEN` 精确命中 1500 行，并断言结果按页号升序且严格递增。
- 既有 zone map 回归（等值/范围/重写失效/`IS NULL`）保持通过。
- 工作区 `cargo test`、`clippy -D warnings`、Windows release 构建与运行时冒烟随后执行；
  musl 静态产物以 CI 为准。

## 边界

- 本版只并行**页解码**，不并行 WAL、不并行写入；OLTP 路径未改动。
- 列裁剪、向量化聚合、优化器真实统计、`mysql.object_*` 仍未实现。
- 未重跑同机 MySQL 对比基准，因此不声明固定加速倍数；收益取决于候选页数、CPU 核数、
  页面缓存命中率与磁盘吞吐。
- `MYDB_OLAP_SCAN_THREADS` 为进程级一次性读取，运行中修改需重启。
